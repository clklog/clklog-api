## P0-1 Cookie 明文存密码

### 改前要点
```js
// login/index.vue（旧）
Cookies.set("userInfo", JSON.stringify(this.loginForm));
// loginForm = { username, password }  —— 密码明文进 Cookie
```

### 策略
Cookie 只存 `{ username }`；密码仅登录请求使用。新增 `userInfo.js` 统一读写，兼容历史带 password 的 Cookie。

### 改后关键代码
```js
// clklog-ui/src/utils/userInfo.js
export function setRememberedUsername(username) {
  Cookies.set(USER_INFO_KEY, JSON.stringify({
    username: username ? String(username).trim() : ''
  }))
}

export function getRememberedUsername() {
  // ...
  if (info && Object.prototype.hasOwnProperty.call(info, 'password')) {
    setRememberedUsername(username) // 读到旧 Cookie 立即覆写
  }
  return username
}
```

```js
// login 成功后
setRememberedUsername(this.loginForm.username.trim());
```

## P0-3 崩溃原因 `v-html` XSS

### 改前要点
```vue
<div v-html="filterReason(rowList.appCrashedReason)"></div>
<!-- filterReason 仅 replace(/\n/g, '<br/>')，未转义 HTML -->
```

### 策略
去掉 `v-html`，用文本插值 + `white-space: pre-wrap`；`filterReason` 只把字面量 `\n` 转成真换行。

### 改后关键代码
```vue
<div class="crash-reason">{{ filterReason(rowList.appCrashedReason) }}</div>
```

```js
filterReason(str) {
  if (!str) return "";
  return String(str)
    .replace(/\\r\\n/g, "\n")
    .replace(/\\n/g, "\n")
    .replace(/\\r/g, "\n")
    .replace(/\r\n/g, "\n")
    .replace(/\r/g, "\n");
}
```

```css
.crash-reason {
  white-space: pre-wrap;
  word-break: break-word;
}
```

**文件：** `clklog-ui/src/views/collapse-analysis/components/collapseDetail-dialog.vue`

## P0-4 Token 使用 `innerHTML`

### 改前要点
```js
hideItem.innerHTML = row.token; // Token 写入 innerHTML，有 XSS 风险
```

### 策略
Vue 数据 `_tokenVisible` 切换显示；模板 `{{ }}` 绑定。

### 改后关键代码
```vue
<span>{{
  scope.row._tokenVisible
    ? scope.row.token
    : "****************************************************"
}}</span>
<i @click="toggleTokenVisible(scope.row)" ... />
```

```js
toggleTokenVisible(row) {
  this.$set(row, "_tokenVisible", !row._tokenVisible);
}
```

**文件：** `clklog-ui/src/views/sys-manage/app-manage.vue`

## P0-6 硬编码 DB / JWT / Redis（后端）

### 改前要点
```yaml
password: 123456
token.secret: c609737e578978eccc64cef4be680   # api/manage 相同弱密钥硬编码
```

### 策略
改为 `${ENV:默认值}`；生产用环境变量覆盖。  
**关键：** api 与 manage 必须共用同一 JWT 密钥（登录在 manage 签发、业务在 api 校验）。曾误拆两把密钥会导致全站 403，已改回共享默认。

### 改后关键代码
```yaml
# clklog-api & clklog-manage 的 application.yml（两端默认值必须一致）
spring.datasource.*.password: ${MYSQL_PASSWORD:123456}   # 或 CLICKHOUSE_PASSWORD
token:
  secret: ${TOKEN_SECRET:clklog-shared-change-me-use-env-token-secret-at-least-32chars}
```

## P0-8 CORS `credentials + *`

### 改前要点
```java
config.setAllowCredentials(true);
config.addAllowedOriginPattern("*"); // 任意来源带凭据
```

### 策略
支持逗号分隔多域名；配置为单独 `*` 时自动 `allowCredentials=false`；默认保持 `*` 以免生产未配域名时跨域全挂。

### 改后关键代码
```java
boolean wildcardOnly = "*".equals(patterns);
config.setAllowCredentials(!wildcardOnly);
for (String pattern : patterns.split(",")) {
    if (StringUtils.hasText(trimmed)) {
        config.addAllowedOriginPattern(trimmed);
    }
}
```

```yaml
access-control-allow-origin-patterns: ${CORS_ORIGIN_PATTERNS:*}
```

**文件：** api/manage `ResourcesConfig.java`
